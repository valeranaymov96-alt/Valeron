# Valeron

Небольшой учебный проект на Python 3. Скрипт выводит приветствие `World!!!`.

## Запуск

Из папки проекта выполните:

```bash
python tes.py
```

Дополнительные библиотеки не нужны. При импорте `tes` сообщение не выводится;
для вывода можно вызвать функцию `tes.p()`.

## Задание для друга: Selenium на готовом сайте

**Цель:** написать браузерные тесты на Python для готовой
[учебной формы Selenium](https://www.selenium.dev/selenium/web/web-form.html).
Это публичная страница из официального учебника Selenium. Создавать сайт,
писать HTML или запускать локальный сервер не нужно. Нужны Chrome и интернет.

### 1. Подготовка

1. Открой страницу вручную и попробуй поля, флажки и кнопку Submit.
2. Создай виртуальное окружение из корня проекта:

   ```bash
   python -m venv .venv
   ```

3. Установи Selenium в это окружение (команда для Windows):

   ```powershell
   .\.venv\Scripts\python.exe -m pip install selenium
   ```

4. Создай `selenium_tests/test_web_form.py`. Используй `unittest` и Selenium
   WebDriver. Каждый сценарий ниже оформи отдельным методом `test_...`.
5. Добавь `.venv/` и `__pycache__/` в `.gitignore`.

### 2. Обязательные сценарии

| № | Действия | Что проверить |
| --- | --- | --- |
| 1 | Открыть форму | Заголовок вкладки — `Web form`, кнопка Submit видна и доступна |
| 2 | В поле Text input ввести `Selenium` | Значение поля точно равно введённому тексту |
| 3 | Ввести текст в Text input, очистить и ввести `Hello` | В поле только `Hello`, старый текст удалён |
| 4 | В Textarea ввести две строки | Значение сохраняет обе строки и перевод строки |
| 5 | Найти Disabled input | Поле отключено: `is_enabled()` возвращает `False` |
| 6 | Найти Checked checkbox и нажать на него | Сначала выбран, после нажатия не выбран |
| 7 | Найти Default checkbox и нажать на него | Сначала не выбран, после нажатия выбран |
| 8 | Ввести `Selenium` в Text input и нажать Submit | Открылась страница с путём `/selenium/web/submitted-form.html`, виден текст `Received!` |

В сценарии 8 проверяй путь URL отдельно от параметров после `?`:
при отправке формы они могут добавляться к адресу.

### 3. Подсказки и требования к тестам

- Начинай каждый тест с новой сессии браузера и исходной страницы формы.
- Регистрируй закрытие браузера через `self.addCleanup(driver.quit)` сразу
  после его создания: браузер должен закрыться и при ошибке проверки.
- Ищи элементы по `id`, `name` или понятному CSS-селектору через `By`.
  Найти атрибуты можно в инструментах разработчика браузера (F12).
- Для первого поля можно начать с `By.NAME, "my-text"`, а сообщение после
  отправки искать по `By.ID, "message"`.
- Значение поля проверяй через `get_property("value")`, состояние флажка —
  через `is_selected()`. Каждому сценарию нужна проверка `assert...`.
- Используй `WebDriverWait` для ожидания элементов и результата отправки.
  Не смешивай явные и неявные ожидания, не используй `time.sleep()`.
- Сначала добейся работы одного простого теста, затем добавляй остальные.

Материалы: [первый скрипт Selenium](https://www.selenium.dev/documentation/webdriver/getting_started/first_script/)
и [ожидания](https://www.selenium.dev/documentation/webdriver/waits/).

### 4. Запуск и результат

После создания тестов запускай их из корня проекта:

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s selenium_tests -p "test_*.py" -v
```

**Задание готово, когда:**

- Все восемь тестов проходят, браузеры после запуска закрываются.
- Тесты можно запускать независимо друг от друга.
- Ты убедился, что проверка работает: временно заменил ожидаемый заголовок
  на неправильный, получил падение теста и вернул правильное значение.
- В `requirements-selenium.txt` записана использованная версия Selenium
  в формате `selenium==версия`, а в README описана установка из этого файла.
- В `selenium_tests/REPORT.md` указаны версии Python, Chrome и Selenium,
  команда запуска, число пройденных тестов и возникшие сложности.

**Дополнительно, по желанию:** headless-режим Chrome и скриншот при падении.
Само решение нужно написать другу; в этом разделе приведено только задание.

### 5. Подробные тест-кейсы

**Общие предусловия:** Chrome установлен, интернет доступен. Перед каждым
кейсом открой новую сессию браузера и перейди на
https://www.selenium.dev/selenium/web/web-form.html.
Дождись загрузки формы. После каждого кейса закрой браузер.

Сначала выполни шаги вручную, затем автоматизируй их в указанном методе
файла `selenium_tests/test_web_form.py`. Проверяй каждый ожидаемый результат,
а не только отсутствие ошибки в коде.

#### TC-01 — Открытие формы

Метод: `test_form_is_available`.

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Открой страницу по ссылке из предусловий | Отображается форма |
| 2 | Прочитай заголовок вкладки | Точное значение: `Web form` |
| 3 | Найди кнопку Submit | Кнопка видна и доступна для нажатия |

**В автотесте:** сравни `driver.title` с ожидаемой строкой, проверь
`is_displayed()` и `is_enabled()` у кнопки. Нажимать её в этом кейсе не нужно.

#### TC-02 — Ввод текста

Метод: `test_text_input_accepts_text`. Данные: `Selenium`.

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Найди поле Text input и очисти его | Поле пустое |
| 2 | Введи `Selenium` | Текст появился в поле |
| 3 | Прочитай значение поля | Оно точно равно `Selenium` |

**В автотесте:** используй `clear()`, `send_keys()` и сравнение
`get_property("value")` с тестовыми данными. Форму отправлять не нужно.

#### TC-03 — Очистка и замена текста

Метод: `test_text_input_can_be_replaced`. Данные: `Selenium`, затем `Hello`.

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | В пустое поле Text input введи `Selenium` | Значение равно `Selenium` |
| 2 | Полностью очисти поле | Значение равно пустой строке |
| 3 | Введи `Hello` | Значение равно `Hello`, старого текста нет |

**В автотесте:** проверь значение после каждого шага. Этот кейс самостоятельно
вводит исходный текст и не зависит от выполнения TC-02.

#### TC-04 — Многострочный текст

Метод: `test_textarea_preserves_line_breaks`.
Данные: первая строка `First line`, вторая строка `Second line`.

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Найди Textarea и очисти его | Поле пустое |
| 2 | Введи `First line`, перевод строки и `Second line` | Видны две строки |
| 3 | Прочитай значение Textarea | Обе строки сохранены в исходном порядке с одним переводом строки |

**В автотесте:** передай строку `"First line\nSecond line"` в `send_keys()`
и сравни значение поля с этой же строкой. Здесь `\n` — перевод строки,
а не два символа обратной косой черты и буквы n.

#### TC-05 — Отключённое поле

Метод: `test_disabled_input_is_disabled`.

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Найди поле с подписью Disabled input | Поле видно на странице |
| 2 | Проверь, доступно ли оно для ввода | Поле отключено |

**В автотесте:** проверь `is_displayed()` и то, что `is_enabled()` равно
`False`. Вводить текст в отключённое поле для этого кейса не требуется.

#### TC-06 — Снятие установленного флажка

Метод: `test_checked_checkbox_can_be_unchecked`.

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Найди Checked checkbox | Флажок изначально установлен |
| 2 | Нажми на него один раз | Отметка снята |

**В автотесте:** проверь `is_selected()` до клика (`True`)
и после клика (`False`).

#### TC-07 — Установка пустого флажка

Метод: `test_default_checkbox_can_be_checked`.

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Найди Default checkbox | Флажок изначально не установлен |
| 2 | Нажми на него один раз | Отметка появилась |

**В автотесте:** проверь `is_selected()` до клика (`False`)
и после клика (`True`). Это другой флажок, не тот, что в TC-06.

#### TC-08 — Отправка формы

Метод: `test_form_submission_shows_confirmation`. Данные: `Selenium`.

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Введи `Selenium` в Text input | Значение поля равно `Selenium` |
| 2 | Нажми Submit | Браузер переходит на страницу результата |
| 3 | Дождись появления сообщения | Видно сообщение с точным текстом `Received!` |
| 4 | Проверь путь текущего URL | Путь равен `/selenium/web/submitted-form.html` |

**В автотесте:** дождись видимости элемента с `id="message"` через
`WebDriverWait`, затем сравни его текст. Для проверки пути можно использовать
`urllib.parse.urlparse(driver.current_url).path`; параметры запроса не сравнивай.
Этот кейс проверяет подтверждение отправки, а не сохранение данных на сервере.
