# Valeron

Небольшой учебный проект на Python 3. Скрипт выводит приветствие `World!!!`.

## Запуск

Из папки проекта выполните:

```bash
python tes.py
```

Дополнительные библиотеки не нужны. При импорте `tes` сообщение не выводится;
для вывода можно вызвать функцию `tes.p()`.

## Задание для друга: Selenium на готовом сайте

**Цель:** написать браузерные тесты на Python для готовой
[учебной формы Selenium](https://www.selenium.dev/selenium/web/web-form.html).
Это публичная страница из официального учебника Selenium. Создавать сайт,
писать HTML или запускать локальный сервер не нужно. Нужны Chrome и интернет.

### 1. Подготовка

1. Открой страницу вручную и попробуй поля, флажки и кнопку Submit.
2. Создай виртуальное окружение из корня проекта:

   ```bash
   python -m venv .venv
   ```

3. Установи Selenium в это окружение (команда для Windows):

   ```powershell
   .\.venv\Scripts\python.exe -m pip install selenium
   ```

4. Создай `selenium_tests/test_web_form.py`. Используй `unittest` и Selenium
   WebDriver. Каждый сценарий ниже оформи отдельным методом `test_...`.
5. Добавь `.venv/` и `__pycache__/` в `.gitignore`.

### 2. Обязательные сценарии

| № | Действия | Что проверить |
| --- | --- | --- |
| 1 | Открыть форму | Заголовок вкладки — `Web form`, кнопка Submit видна и доступна |
| 2 | В поле Text input ввести `Selenium` | Значение поля точно равно введённому тексту |
| 3 | Ввести текст в Text input, очистить и ввести `Hello` | В поле только `Hello`, старый текст удалён |
| 4 | В Textarea ввести две строки | Значение сохраняет обе строки и перевод строки |
| 5 | Найти Disabled input | Поле отключено: `is_enabled()` возвращает `False` |
| 6 | Найти Checked checkbox и нажать на него | Сначала выбран, после нажатия не выбран |
| 7 | Найти Default checkbox и нажать на него | Сначала не выбран, после нажатия выбран |
| 8 | Ввести `Selenium` в Text input и нажать Submit | Открылась страница с путём `/selenium/web/submitted-form.html`, виден текст `Received!` |

В сценарии 8 проверяй путь URL отдельно от параметров после `?`:
при отправке формы они могут добавляться к адресу.

### 3. Подсказки и требования к тестам

- Начинай каждый тест с новой сессии браузера и исходной страницы формы.
- Регистрируй закрытие браузера через `self.addCleanup(driver.quit)` сразу
  после его создания: браузер должен закрыться и при ошибке проверки.
- Ищи элементы по `id`, `name` или понятному CSS-селектору через `By`.
  Найти атрибуты можно в инструментах разработчика браузера (F12).
- Для первого поля можно начать с `By.NAME, "my-text"`, а сообщение после
  отправки искать по `By.ID, "message"`.
- Значение поля проверяй через `get_property("value")`, состояние флажка —
  через `is_selected()`. Каждому сценарию нужна проверка `assert...`.
- Используй `WebDriverWait` для ожидания элементов и результата отправки.
  Не смешивай явные и неявные ожидания, не используй `time.sleep()`.
- Сначала добейся работы одного простого теста, затем добавляй остальные.

Материалы: [первый скрипт Selenium](https://www.selenium.dev/documentation/webdriver/getting_started/first_script/)
и [ожидания](https://www.selenium.dev/documentation/webdriver/waits/).

### 4. Запуск и результат

После создания тестов запускай их из корня проекта:

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s selenium_tests -p "test_*.py" -v
```

**Задание готово, когда:**

- Все восемь тестов проходят, браузеры после запуска закрываются.
- Тесты можно запускать независимо друг от друга.
- Ты убедился, что проверка работает: временно заменил ожидаемый заголовок
  на неправильный, получил падение теста и вернул правильное значение.
- В `requirements-selenium.txt` записана использованная версия Selenium
  в формате `selenium==версия`, а в README описана установка из этого файла.
- В `selenium_tests/REPORT.md` указаны версии Python, Chrome и Selenium,
  команда запуска, число пройденных тестов и возникшие сложности.
